자바 다중 catch와 throw — 예외마다 다르게 대응하기(MULTI-CATCH·THROW)

PANCO_IT2026년 8월 10일 09:50
#자바#JAVA#예외처리#다중catch#throw

예외 종류마다 다른 catch로 갈라 잡으면, 원인에 맞는 대응을 할 수 있습니다.

지난 편에서 try-catch로 안전망을 치는 법을 배웠습니다. 그런데 한 코드 안에서 예외가 여러 종류로 날 수 있다면 어떡할까요. 0으로 나눌 수도 있고, 배열 범위를 벗어날 수도 있죠. 오늘은 여러 예외를 각각 다르게 잡는 법과, 내가 직접 예외를 만들어 던지는 법을 배웁니다.

예외마다 원인이 다릅니다

같은 코드 블록 안에서도 예외는 여러 종류로 날 수 있습니다. catch를 하나만 두면 "뭐가 잘못됐는지"는 알아도 "왜 잘못됐는지"는 뭉뚱그려집니다.

int[] nums = {10, 20, 30};
int a = nums[5];       // 배열 범위 밖 (IndexOutOfBounds)
int b = 10 / 0;         // 0으로 나눔 (Arithmetic)

두 줄 다 예외지만 원인이 다릅니다. 원인마다 다른 안내를 하고 싶다면, catch를 여러 개 두면 됩니다.

다중 catch — 여러 개를 나란히

catch 블록을 여러 개 연달아 쓰면, 자바는 발생한 예외 종류에 맞는 블록을 찾아 실행합니다.

try {
    int[] nums = {10, 20, 30};
    System.out.println(nums[5]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("배열 범위를 벗어났습니다.");
} catch (ArithmeticException e) {
    System.out.println("0으로 나눌 수 없습니다.");
} catch (Exception e) {
    System.out.println("알 수 없는 문제가 발생했습니다: " + e.getMessage());
}

세 번째 catch (Exception e)는 모든 예외를 다 잡는 포괄 catch입니다. 앞의 두 catch에 안 걸린 나머지 예외가 여기로 옵니다. 위 코드는 nums[5]에서 배열 범위 예외가 나므로 첫 번째 catch가 실행됩니다.

catch 순서가 중요합니다

여기서 자주 하는 실수가 있습니다. 포괄적인 Exception을 맨 앞에 두는 것입니다.

try {
    int[] nums = {10, 20, 30};
    System.out.println(nums[5]);
} catch (Exception e) {                          // 모든 예외를 다 가로챔
    System.out.println("문제가 생겼습니다.");
} catch (ArrayIndexOutOfBoundsException e) {      // 여기는 절대 실행 안 됨!
    System.out.println("배열 범위를 벗어났습니다.");
}

Exception은 거의 모든 예외의 부모라서, 맨 앞에 두면 뒤에 있는 구체적인 catch가 아예 실행될 기회를 잃습니다. 이 코드는 컴파일 오류(도달할 수 없는 코드)까지 발생시킵니다. 그래서 규칙은 하나입니다. 구체적인 예외를 먼저, 포괄적인 예외는 맨 마지막에 둡니다.

throw — 내가 직접 예외를 던지기

지금까지는 자바가 알아서 예외를 만들어 줬습니다. 그런데 "이 상황은 내가 봐도 잘못됐다"고 판단되면, 직접 예외를 만들어 던질 수도 있습니다. 이때 쓰는 키워드가 throw입니다.

static void checkAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("나이는 음수일 수 없습니다.");
    }
    System.out.println("나이: " + age);
}

checkAge(-5)를 부르면, 자바가 예외를 만나서가 아니라 내가 조건을 검사해 직접 예외를 발생시킵니다. 이렇게 하면 "나중에 이상한 값으로 계산하다 애매하게 죽는" 대신, 문제가 생긴 그 자리에서 명확하게 알릴 수 있습니다.

그림 1. throw는 실제로 던지는 동작, throws는 "던질 수 있다"고 미리 알리는 선언입니다.

throw와 throws는 다릅니다

이름이 비슷해 헷갈리기 쉬운 단어가 하나 더 있습니다. throws(s가 붙음)입니다.

static void readFile() throws IOException {   // throws: "이 메서드는 예외가 날 수 있다"고 알림
    // 파일 읽는 코드 (실제로 예외가 날 수 있는 부분)
}

throw는 메서드 안에서 실제로 예외를 발생시키는 실행문이고, throws는 메서드 이름 옆에 붙여 "이 메서드를 쓰면 이런 예외가 날 수 있다"고 미리 알리는 선언입니다. 이 선언을 보면 이 메서드를 부르는 쪽에서 try-catch로 대비할 수 있습니다.

단골 함정 — 무조건 Exception만 잡기

또 하나 흔한 습관은, 무슨 예외인지 따지지 않고 항상 catch (Exception e) 하나로만 처리하는 것입니다. 컴파일은 되지만, 어떤 문제인지 구분이 안 돼 디버깅이 어려워집니다. "0으로 나눴는지, 배열이 넘쳤는지, 파일이 없는지"를 알아야 정확한 대응이 가능합니다. 가능하면 예상되는 예외는 구체적으로 잡고, 정말 예상 못 한 것만 마지막에 포괄 catch로 받는 것이 좋은 습관입니다.

직접 실행해 보기

아래 코드를 돌려 보고, 나이를 음수로 바꿔 throw가 어떻게 동작하는지, 배열 인덱스를 바꿔 다중 catch가 어떻게 갈라지는지 확인해 보세요.

다중 catch와 throw
public class Main {
  static void checkAge(int age) {
      if (age < 0) {
          throw new IllegalArgumentException("나이는 음수일 수 없습니다.");
      }
      System.out.println("나이 확인 완료: " + age);
  }

  public static void main(String[] args) {
      try {
          int[] nums = {10, 20, 30};
          System.out.println(nums[5]);       // 배열 범위 밖
      } catch (ArrayIndexOutOfBoundsException e) {
          System.out.println("배열 범위를 벗어났습니다.");
      } catch (ArithmeticException e) {
          System.out.println("0으로 나눌 수 없습니다.");
      }

      try {
          checkAge(-5);
      } catch (IllegalArgumentException e) {
          System.out.println("직접 던진 예외: " + e.getMessage());
      }
  }
}

📱 코드 실행(실습)은 태블릿·PC에서 이용할 수 있어요. 모바일에서는 위 코드를 눈으로 따라가며 확인하세요.

한 장 정리

키워드뜻
다중 catch예외 종류마다 다른 catch로 대응
catch 순서구체적인 것 먼저, 포괄적인(Exception) 것은 마지막
throw메서드 안에서 직접 예외를 발생시키는 실행문
throws메서드 선언부에 "예외가 날 수 있다"고 알리는 표시
함정항상 Exception만 잡으면 원인 구분이 안 됨

이것만 기억하면 됩니다. 예외 종류가 여러 개면 catch를 나란히 두되, 구체적인 것을 먼저 씁니다. throw는 내가 직접 예외를 던지는 동작, throws는 "예외가 날 수 있다"는 사전 알림입니다. 이 둘을 구분해 쓰면 오류의 원인이 훨씬 선명해집니다.
