CLAUDE.md 작성법, 63줄에 26KB가 된 이유

PANCO_IT2026년 10월 21일 08:44
#CLAUDE.md#클로드코드#ClaudeCode#CLAUDE.md작성법#AI에이전트

그림 1. 글쓰기 작업 저장소의 CLAUDE.md, 커밋 60번 동안의 크기와 줄 수 (출처: 이 PC의 git 기록을 ECharts로 그림, 2026-10-21)

CLAUDE.md는 Claude Code가 세션을 시작할 때마다 읽는 지시 파일입니다. 공식 문서는 한 파일을 200줄 아래로 두라고 권합니다. 제가 6주 동안 60번 고친 CLAUDE.md는 63줄이라 그 기준 안쪽인데, 크기는 5.6KB에서 26.7KB로 4.7배가 됐습니다. 줄 수만 세면 놓치는 부분입니다.

2026년 10월 21일, 이 글을 쓰는 PC(윈도우 11, Claude Code 2.1.146)에서 git log --follow -- CLAUDE.md로 커밋마다 크기·줄 수·가장 긴 줄을 쟀습니다. 여러 채널의 글쓰기 작업을 에이전트에게 맡기는 저장소라, 파일에 적힌 계정·주소·채널 이름은 이 글에 옮기지 않았습니다.

CLAUDE.md는 어디에 두나

공식 문서가 정한 위치는 넷입니다. 넓은 범위부터 읽고, 모두 이어 붙여 함께 읽습니다(덮어쓰지 않습니다).

위치쓰임
관리 정책 — 윈도우 C:\Program Files\ClaudeCode\CLAUDE.md회사가 모든 사용자에게 거는 지시
사용자 — ~/.claude/CLAUDE.md내 모든 프로젝트에 적용할 습관
프로젝트 — ./CLAUDE.md 또는 ./.claude/CLAUDE.md저장소에 함께 올리는 팀 공용 지시
로컬 — ./CLAUDE.local.md나만 쓰는 프로젝트 설정(.gitignore에 넣음)

Claude Code는 시작한 폴더와 그 위 폴더들의 CLAUDE.md를 모두 읽습니다. 아래 하위 폴더의 CLAUDE.md는 시작할 때가 아니라, 그 폴더의 파일을 읽거나 고칠 때 불러옵니다. 처음 만들 때는 세션에서 /init을 입력하면 저장소를 보고 빌드 명령·테스트 방법 같은 초안을 만들어 줍니다.

제 저장소는 프로젝트 CLAUDE.md 하나만 씁니다. 사용자 파일(~/.claude/CLAUDE.md)은 이 PC에 없습니다.

6주 동안 무엇이 늘었나

처음 커밋(9월 7일)은 40줄 5,626바이트였습니다. 마지막 커밋(10월 19일)은 63줄 26,651바이트입니다. 줄은 23줄 늘었고 크기는 4.7배가 됐습니다.

늘어난 이유는 가장 긴 줄을 보면 나옵니다. 처음 410자였던 가장 긴 줄이 지금은 1,055자입니다. 새 지시를 받을 때마다 새 줄을 만들지 않고, 관련된 줄 끝에 "(날짜 · 지시 원문 · 바뀐 규칙)"을 덧붙여 왔기 때문입니다. 줄 수는 그대로 두면서 한 줄이 문단이 됐습니다.

그림 2. 가장 긴 한 줄의 글자 수 (출처: 이 PC의 git 기록을 ECharts로 그림, 2026-10-21)

공식 문서의 200줄 기준은 "길수록 맥락을 더 쓰고 지시를 덜 따른다"는 이유에서 나옵니다. 한 줄이 1,000자를 넘으면 줄 수로는 그 비용이 보이지 않습니다. 저라면 줄 수와 함께 파일 크기(KB)도 같이 봅니다.

그림 3. 공식 문서의 "Write effective instructions" 절 (출처: code.claude.com/docs/en/memory, 2026-10-21 캡처)

60번 고치면서 남긴 쓰는 법

확인할 수 있는 문장으로 씁니다

공식 문서의 예처럼 "코드를 정리하라" 대신 "커밋 전에 npm test를 돌린다"처럼 씁니다. 제 파일에는 시각 계산에 쓸 명령을 이렇게 박아 두었습니다.

발행 시각 계산은 date '+%Y-%m-%dT%H:%M' 로 한다.
TZ=Asia/Seoul date 는 이 환경에서 UTC를 돌려준다.

두 번째 줄은 이 환경에서만 생기는 함정을 그대로 적은 것입니다. "시간대에 주의하라"보다 어느 명령이 틀리는지를 적어야 에이전트가 같은 명령을 다시 쓰지 않습니다.

맨 위에는 사람이 할 일을 둡니다

파일 첫 절은 "에이전트가 하지 않는 일" 목록입니다. 외부에 올리는 일은 사람이 승인한 뒤에만 하고, 로그인·비밀번호·삭제·계정 설정은 사람이 한다는 줄입니다. 여러 세션이 같은 저장소를 고치므로 작업 전에 최신 상태를 받는다는 줄도 여기 있습니다. 같은 작업이 두 번 실행된 일이 있은 뒤 넣은 줄입니다.

세부 규칙은 다른 파일로 빼고 가리킵니다

CLAUDE.md에는 "무엇을 하려면 어느 문서를 읽으라"만 두고, 세부 규칙은 저장소 안 규칙 폴더의 문서 52개로 나눴습니다. @경로로 가져오지(import) 않고 경로만 적었습니다. 공식 문서에 따르면 import한 파일은 시작할 때 함께 읽혀 맥락 비용이 줄지 않습니다. 경로만 적어 두면 에이전트가 그 작업을 할 때 열어 봅니다.

import를 쓴다면 경로의 빈칸에 주의합니다. 공식 문서는 빈칸 앞에 백슬래시를 붙이라고 하고, 따옴표로 감싼 경로는 아예 가져오지 않는다고 적었습니다. 한국어 윈도우의 바탕 화면 폴더처럼 이름에 빈칸이 있는 경로가 여기에 걸립니다. import는 최대 네 단계까지 이어집니다.

문장으로 못 막는 일은 검사로 막습니다

공식 문서는 CLAUDE.md가 "강제 설정이 아니라 맥락"이라고 적습니다. 반드시 막아야 하는 동작은 훅(PreToolUse hook)으로 막으라고 합니다. 제 저장소는 같은 실수가 두 번 나오면 CLAUDE.md에 한 줄을 더 쓰는 대신 발행 전에 도는 검사 스크립트에 조건을 넣었습니다. CLAUDE.md에는 "이 검사를 통과해야 발행한다"는 한 줄만 남깁니다.

지금 파일에서 고칠 것

가장 긴 줄들은 특정 작업에만 필요한 지시입니다. 공식 문서는 이런 지시를 .claude/rules/ 폴더의 규칙 파일로 옮기고, 파일 앞머리 paths에 경로를 적으면 그 경로의 파일을 다룰 때만 읽힌다고 안내합니다. 1,000자 가까운 줄부터 이렇게 옮길 생각입니다.

지시끼리 어긋나는지 점검해 주는 /doctor prompt-audit도 문서에 있지만, Claude Code v2.1.283 이상에서만 됩니다. 이 PC는 2.1.146이라 아직 쓸 수 없었습니다.
