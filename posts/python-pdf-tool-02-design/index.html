1편에서 무엇을 만들지는 정했습니다. 그런데 막상 코드를 짜려고 하니, 버튼을 눌렀을 때 무엇부터 해야 하는지가 머릿속에서 잘 그려지지 않았습니다.

그래서 코드 대신 흐름도부터 그렸습니다. 그림은 1편과 마찬가지로 draw.io로 그렸습니다.

처리 흐름도

파일을 고르는 데서 시작해 결과 파일이 나올 때까지를 순서도로 그려 보니 이렇게 됐습니다.

그리다 보니 결과를 어디에 저장할지부터 걸렸습니다. 원본 위에 덮어쓰는 건 생각만 해도 불안해서, 결과는 무조건 새 파일로 저장하기로 했습니다.

처음 그린 흐름도에서는 PDF를 합치든 사진을 묶든 저장한 다음에 용량을 확인하게 해 두었습니다. 1편 요구사항을 다시 읽어 보니 용량은 사진을 묶을 때만 줄이기로 정해 놓았는데, 이대로면 PDF를 합칠 때도 용량 제한 칸이 열려 있게 됩니다. 그래서 용량 확인은 사진을 PDF로 바꾼 뒤에만 하고, PDF 합치기는 저장하면 바로 끝나게 고쳤습니다.

용량을 줄이는 방법도 흐름도를 그리면서 정했습니다. 사진을 PDF에 넣을 때는 화질을 0~100 사이 숫자로 정할 수 있어서, 화질부터 낮추는 게 가장 손쉽습니다.

다만 화질만 계속 내리면 서류 사진 속 글자가 뭉개질 것 같았습니다. 그래서 화질은 50 밑으로 내리지 않고, 그래도 정한 용량보다 크면 그때부터 사진 가로세로를 80%씩 줄이기로 했습니다.

화질을 한 번에 10씩 내리는 것과 사진을 80%씩 줄이는 것은 아직 실제 사진으로 재 보지 않고 정한 숫자입니다. 사진을 묶는 코드를 짤 때 직접 돌려 보고 맞는지 다시 보겠습니다.

화면 설계

창 화면도 코드로 바로 짜면 버튼 자리를 몇 번이고 옮기게 될 것 같아서, 먼저 그림으로 그려 봤습니다.

실무에서는 이런 그림을 와이어프레임이라고 합니다. 색이나 글꼴은 신경 쓰지 않고 무엇을 어디에 둘지만 정합니다.

화면에 있는 것들이 각각 무슨 일을 하는지도 적어 뒀습니다.

번호화면 요소하는 일
1할 일 고르기PDF 합치기와 사진 → PDF 중에서 고름
2파일 목록합쳐질 순서대로 보임
3버튼들파일·폴더 추가, 위로·아래로, 빼기
4용량 제한사진 → PDF일 때만 켜짐. 체크하고 MB 숫자를 넣음
5저장 위치같은 이름 파일이 있으면 물어봄
6만들기목록이 비어 있으면 안 눌림
7상태줄끝나면 쪽수와 용량을 보여 줌

같은 이름 파일이 있으면 물어보게 한 건 화면 설명을 적다가 생각났습니다. 말없이 덮어썼는데 그게 지난번에 만들어 둔 파일이면 되돌릴 방법이 없습니다.

모듈 나누기

화면과 기능을 한 파일에 섞어 두면 버튼 하나 옮기다가 합치기 코드까지 건드리게 될 것 같았습니다.

그래서 파일을 둘로 나눴습니다. 창은 pdf_tool_ui.py, 실제로 PDF를 다루는 함수는 pdf_core.py에 두고, 창 쪽에서는 함수를 부르기만 합니다.

번호순은 처음에 pdf_합치기 안에 넣어 둘 생각이었습니다. 그런데 휴대폰 사진도 이름 끝에 번호가 붙어서, 사진을 묶을 때도 같은 순서 문제가 날 수 있었습니다. 그래서 따로 떼어 내 두 함수가 같이 쓰게 했습니다.

함수마다 무엇을 넣으면 무엇이 나오는지, 잘못된 파일이 들어오면 어떻게 할지도 미리 적어 뒀습니다. 이걸 정해 두면 창을 만들 때 기능 코드를 다시 열어 보지 않아도 됩니다.

함수넣는 것나오는 것잘못됐을 때
번호순파일 경로번호 순서로 정렬할 기준-
pdf_합치기PDF 목록, 저장 경로쪽수암호·깨진 파일 이름을 알려 줌
사진_pdf사진 목록, 저장 경로, 화질, 크기쪽수안 열리는 사진 이름을 알려 줌
용량_맞추기사진 목록, 저장 경로, 제한 MB최종 용량끝까지 줄여도 안 되면 알려 줌

창은 tkinter로 만들 생각입니다. 파이썬을 깔면 같이 들어와서 따로 설치할 게 없습니다. 이미 pypdf와 Pillow를 깔아야 하는데, 화면 때문에 하나 더 늘리고 싶지는 않았습니다.

예외 처리

흐름도는 잘 될 때만 그린 거라, 이상한 파일이 들어오면 어떻게 할지도 따로 적었습니다. 아무 처리도 안 하면 프로그램이 오류를 내고 꺼져 버리고, 쓰는 사람은 왜 안 되는지 모릅니다.
