7편에서는 데스크톱 프로그램을 2편에서 만든 시험표대로 처음부터 끝까지 해 봤습니다. 12편에서는 웹 화면까지 붙였습니다. 회사 동료에게 주소를 건네기 전에 웹 버전도 같은 시험을 거쳐야 합니다.

1. 웹 시험표 만들기

7편 시험표를 웹 화면에 맞게 고쳤습니다. 여기에 9편에서 다른 사이트를 써 보며 정한 웹 요구사항 FR-W1~W9를 더했습니다.

더블클릭 실행은 주소를 열고 준비가 끝날 때까지 걸린 시간으로 바꿨습니다. 덮어쓰기 확인은 웹에서는 하지 않았습니다. 같은 이름의 파일이 있으면 크롬이 이름 뒤에 번호를 붙여 따로 저장하니, 덮어쓸 일이 없습니다.

PC 폭은 크롬 창 폭 820픽셀입니다. 휴대폰 폭은 크롬의 휴대폰 화면 흉내 기능(390×844, 터치)으로 봤고, 실제 휴대폰은 아닙니다. 고칠 때마다 손으로 다시 하기는 번거로웠습니다. 그래서 7편처럼 시험 순서를 코드로 적어 두고 크롬에서 실행했습니다.

3. 텍스트 파일과 깨진 파일 안내 고치기

파일 선택 창은 PDF, JPG, PNG만 보여 줍니다. 끌어다 놓을 때는 달랐습니다. 아무 파일이나 들어왔습니다.

12편 코드는 이름이 .pdf로 끝나지 않으면 모두 사진으로 봤습니다. 그래서 회의메모.txt가 "사진 → 1쪽 · 자동으로 세움"으로 목록에 들어갔습니다. 오류는 만들기를 누른 뒤에야 났고, 결과 파일은 하나도 나오지 않았습니다.

반쯤 잘린 PDF는 줄 안에 "열 수 없는 PDF입니다"가 떴습니다. 그런데 쪽 그림 칸에는 "암호", 아래 안내는 "암호가 걸려 있어 넣을 수 없습니다"였습니다. 안내를 만드는 코드가 문제 파일을 모두 암호 파일로 보고 있었습니다.

넣는 순간 문제의 종류를 줄마다 적어 두고, 안내도 그 종류대로 나눴습니다.

const kind = /\.pdf$/i.test(file.name) ? 'pdf' : /\.(jpe?g|png)$/i.test(file.name) ? 'photo' : 'other';
if (kind === 'other') {
  it.bad = 'PDF, JPG, PNG만 넣을 수 있습니다. 이 파일만 빼고 합칩니다.'; it.why = 'type';
}
// PDF는 pdf.js로 열 때 난 오류로 암호와 깨짐을 나눈다
if (e.name === 'PasswordException') { it.why = 'pw'; } else { it.why = 'broken'; }
  • 파일 종류 나누기 (kind): 이름 끝이 .pdf면 PDF, .jpg·.jpeg·.png면 사진, 나머지는 넣을 수 없는 파일로 둡니다.
  • 문제 종류 적기 (why): 암호(pw), 깨짐(broken), 형식(type)을 줄마다 기억해 두고, 아래 안내는 종류별로 "암호를 풀고 다시 저장", "원래 파일을 다시 받기", "PDF나 사진이 아님"을 따로 씁니다.

이제 텍스트 파일은 넣는 순간 빨간 줄이 됩니다. 만들기를 누르면 나머지 PDF 2쪽만 합쳐졌습니다. 깨진 파일은 줄과 안내가 모두 "파일이 깨져"로 시작합니다.

4. 빼기 버튼과 끌어서 순서 바꾸기

12편 화면은 암호 걸린 줄에만 빼기 버튼이 있었습니다. 잘못 넣은 파일 하나를 빼려면 페이지를 새로 열고 처음부터 다시 넣어야 했습니다. 이제 빼기 버튼은 모든 줄에 나옵니다.

FR-W5에는 끌어서 순서 바꾸기도 들어 있는데, 12편 화면은 위아래 버튼뿐이었습니다. 이제는 줄 왼쪽의 손잡이를 잡고 끌면 줄이 따라옵니다. 줄 전체를 잡게 하면 휴대폰에서 목록을 스크롤할 때마다 줄이 끌려가서 손잡이로 정했습니다.

function startDrag(e, li) {
  e.preventDefault();
  const ul = $('list');
  li.classList.add('dragging');
  const onMove = (ev) => {
    let before = null;
    for (const r of ul.children) {
      if (r === li) continue;
      const b = r.getBoundingClientRect();
      if (ev.clientY < b.top + b.height / 2) { before = r; break; }
    }
    if (li.nextSibling !== before) ul.insertBefore(li, before);
  };
  const onEnd = () => {
    window.removeEventListener('pointermove', onMove);
    window.removeEventListener('pointerup', onEnd);
    window.removeEventListener('pointercancel', onEnd);
    li.classList.remove('dragging');
    const order = [...ul.children].map((r) => r._item);
    if (order.some((x, k) => x !== items[k])) { items.splice(0, items.length, ...order); $('order').value = 'list'; }
    render();
  };
  window.addEventListener('pointermove', onMove);
  window.addEventListener('pointerup', onEnd);
  window.addEventListener('pointercancel', onEnd);
}
  • 끄는 동안 자리 찾기 (onMove): 손가락이나 마우스가 어느 줄의 가운데보다 위에 있으면, 끌고 있는 줄이 그 줄 앞에 들어갑니다.
  • 놓았을 때 순서 저장 (onEnd): 화면에 놓인 줄 순서대로 파일 목록을 다시 세우고, 순서 칸을 "넣은 순서"로 바꿉니다. 만들기를 누르면 이 순서 그대로 파이썬에 넘어갑니다.
  • 마우스와 손가락을 함께 받기 (pointermove): 포인터 이벤트는 마우스와 터치를 같은 이름으로 보내 줍니다. 코드 하나로 둘 다 됩니다. 손잡이에는 CSS touch-action: none을 줘서, 손잡이를 잡았을 때는 페이지가 스크롤되지 않습니다.

처음 고친 코드는 움직임을 손잡이에서만 받았습니다. 그랬더니 휴대폰 폭에서 손가락으로 끌 때 세 번째 줄이 두 번째 자리에서 멈췄습니다. 줄을 옮기는 순간 손잡이가 목록에서 잠깐 빠졌다가 다시 들어가는데, 그 뒤로는 손가락 움직임이 손잡이에 오지 않았습니다. 움직임을 창 전체(window)에서 받게 바꾸니 손가락으로도 맨 위까지 올라갑니다.

버튼이 셋이 되자 다른 문제가 생겼습니다. 휴대폰 폭에서 파일 이름이 "스캔 (3)...."처럼 잘렸습니다. 사진 줄의 "자동으로 세움" 표시도 두 줄로 끊겼습니다. 그래서 화면 폭이 480픽셀 이하면 줄 안의 간격과 쪽 그림, 버튼이 조금씩 작아집니다. 이름은 다 보입니다.

5. 내려받기 버튼 옆 만들기 버튼 숨기기

다 만들고 나면 내려받기 버튼 25픽셀 아래에 "PDF 한 파일로 만들기" 버튼이 있었습니다. 휴대폰에서 손가락이 조금만 빗나가도 같은 파일을 처음부터 다시 만듭니다. 파일 다섯 개를 5MB로 만들 때 휴대폰 폭에서 151초가 걸렸습니다. 잘못 누르면 그만큼 또 기다려야 합니다.

이제 다 만든 뒤에는 만들기 버튼이 사라집니다. 파일을 더 넣거나 순서나 용량을 바꾸면 완료 표시가 지워지고 버튼이 다시 나옵니다. 내려받기 버튼과 가장 가까운 입력 칸은 위쪽 결과 용량 칸이 됐습니다. 거리는 PC 폭 275픽셀, 휴대폰 폭 297픽셀입니다.

같은 시험 14가지를 두 폭에서 처음부터 다시 했습니다. W-08을 빼면 13가지 중 11가지가 통과입니다. 두 폭의 결과는 이번에도 같았습니다.

7. 남은 문제

페이지를 열고 파일 하나를 넣을 때까지, 이 사이트 말고도 세 곳에서 파일을 받아 왔습니다.

받아 온 곳건수받은 것
이 사이트7화면 파일, 11편 코드, pypdf
cdn.jsdelivr.net10파이썬 실행기(Pyodide), Pillow, pdf.js
fonts.googleapis.com · fonts.gstatic.com23~24화면 글꼴

내 파일을 밖으로 보내는 요청은 한 건도 없었습니다. 하지만 파이썬 실행기와 글꼴은 다른 곳에서 받아 옵니다. 그 주소가 막히거나 회사 망에서 차단되면 이 도구도 열리지 않습니다. 9편에서 써 본 사이트 하나도 라이브러리 주소 하나 때문에 멈췄습니다.

W-06은 반만 됐습니다. 페이지를 열어 둔 채 인터넷을 끊고 만들면 됩니다. 필요한 파일은 이미 다 받아 둔 뒤입니다. 끊은 채로 페이지를 다시 열면 크롬의 인터넷 연결 없음 화면이 뜹니다.

다음 편에서는 파이썬 실행기와 라이브러리, 글꼴을 사이트에 직접 두고 인터넷을 끊은 채 다시 열어도 쓸 수 있게 해 보겠습니다.

제가 쓴 환경은 Windows 11 노트북, 크롬 157, Pyodide 0.26.4(Pillow 10.2.0), pypdf 6.21.4, pdf.js 4.4.168입니다.
