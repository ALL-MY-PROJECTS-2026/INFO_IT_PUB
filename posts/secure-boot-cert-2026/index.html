보안 부팅 인증서 만료 확인, 10월 19일 전에 볼 문구

PANCO_IT2026년 10월 13일 00:41
#보안부팅인증서#보안부팅인증서만료#SecureBoot#윈도우11#Windows보안#UEFI#갤럭시북

그림. 노트북과 인증서 종이 (자체 제작)

구글 검색창에 '보안 부팅 인증서'를 넣으면 만료, 확인, 수동 업데이트, '업데이트가 불가능한 경우'가 줄줄이 뜹니다. Microsoft가 2011년에 만든 보안 부팅(Secure Boot) 인증서 세 개를 2023년판으로 바꾸고 있고, 그 가운데 마지막인 Windows Production PCA 2011이 2026년 10월 19일에 만료되기 때문입니다.

2026년 10월 13일 아침, 이 글을 쓰는 노트북(삼성 갤럭시 북3 프로 360, Windows 11 Home 25H2)에서 직접 확인했습니다. Windows 보안 앱에는 "보안 부팅이 켜져 있고 필요한 모든 인증서 업데이트가 적용되었습니다"라는 문구가 떠 있었습니다. 그 문구에 닿기까지 무엇을 열었고 어디서 막혔는지, 내 PC에 다른 문구가 보이면 무엇을 하면 되는지를 Microsoft 지원 문서와 삼성전자 공지를 함께 열어 적었습니다.

이 노트북의 Windows 보안 앱에 뜬 문구

시작 메뉴에서 'Windows 보안'을 검색해 열고, 왼쪽에서 장치 보안을 누르면 맨 아래쪽에 보안 부팅 칸이 있습니다. 이 노트북에서는 아래 그림처럼 나왔습니다.

그림 1. 갤럭시 북3 프로 360의 Windows 보안 > 장치 보안 > 보안 부팅 (출처: 이 글을 쓴 노트북 화면, 2026-10-13 캡처)

보안 부팅은 PC 전원을 켰을 때 Windows보다 먼저 도는 펌웨어(UEFI)가, 다음에 실행할 부팅 프로그램에 믿을 수 있는 서명이 붙어 있는지 확인하는 기능입니다. 서명이 없거나 차단 목록에 오른 프로그램은 실행하지 않습니다. 이때 '믿을 수 있는 서명'의 기준이 펌웨어 안에 저장된 인증서이고, 그 인증서에 유효기간이 있습니다.

Microsoft 문서 KB5087130에 따르면 이 칸은 2026년 4월부터 Windows 보안 앱에 나타났습니다. 문서에 적힌 주의할 점은 하나입니다. 녹색 확인 표시만으로는 인증서가 바뀌었는지 알 수 없고, 위 그림과 같은 '필요한 모든 인증서 업데이트가 적용되었습니다' 문구까지 확인해야 한다는 것입니다.

만료되는 인증서 셋, 마지막이 10월 19일

아래는 Microsoft 총괄 문서(KB5062710)에 실린 만료 표입니다. 2026년 5월 18일 개정판부터 만료일이 일(日) 단위까지 들어갔습니다.

만료되는 인증서만료일새 인증서하는 일
Microsoft Corporation KEK CA 20112026년 6월 24일Microsoft Corporation KEK 2K CA 2023DB·DBX 업데이트에 서명
Microsoft UEFI CA 20112026년 6월 27일Microsoft UEFI CA 2023 · Microsoft Option ROM UEFI CA 2023다른 회사 부팅 로더·옵션 ROM에 서명
Microsoft Windows Production PCA 20112026년 10월 19일Windows UEFI CA 2023Windows 부팅 로더에 서명

용어 셋만 풀면 표가 읽힙니다. DB는 '실행해도 되는 서명' 목록이고, DBX는 '실행하면 안 되는 서명' 목록입니다. KEK는 이 두 목록을 고칠 권한을 가진 키입니다. 6월에 만료된 두 개는 목록을 고치는 쪽과 다른 회사 프로그램을 확인하는 쪽이었고, 10월 19일에 만료되는 하나는 Windows 자신의 부팅 관리자를 확인하는 쪽입니다.

그림 2. 2011 인증서 세 개의 만료일 (출처: Microsoft KB5062710을 바탕으로 자체 제작)

그림 3. 인증서 만료 표 원문 (출처: Microsoft 지원 KB5062710 「Windows 보안 부팅 인증서 만료 및 CA 업데이트」, 2026-10-13 캡처)

만료일이 지나면 PC가 안 켜지나요

켜집니다. 부팅도, 일반 업데이트도 그대로입니다. Microsoft는 2026년 2월에 낸 문서(KB5079373)에서 새 인증서를 받지 못한 기기도 계속 정상적으로 시작되고, 표준 Windows 업데이트도 계속 설치된다고 밝혔습니다. 일상적인 앱, 인터넷, 검색 같은 기능도 그대로입니다.

받지 못하게 되는 것은 부팅 단계의 보안 수정입니다. Windows 부팅 관리자 업데이트, DB·DBX 목록 갱신, 새로 발견된 부팅 단계 취약점에 대한 수정이 여기에 들어갑니다. 2026년 6월 29일 문서(KB5105943)는 이 상태를 "즉각적인 위험이나 시스템 오류"가 아니라 장기적인 보안이 점점 줄어드는 것으로 설명합니다.

그림 4. 만료 뒤 계속되는 것과 멈추는 것 (출처: Microsoft 지원 KB5079373 「Windows 디바이스에서 보안 부팅 인증서가 만료되는 경우」, 2026-10-13 캡처)

같은 문서에 한 줄이 더 있습니다. 인증서 만료 문제를 피하려고 보안 부팅을 끄면 안 된다는 것입니다. 끄면 이미 알려진 공격에 대한 보호까지 사라집니다.

첫 확인 명령은 '액세스 거부'로 막혔습니다

화면 문구 말고 값으로도 보고 싶어서 PowerShell을 열었습니다. 보안 부팅이 켜져 있는지 묻는 기본 명령은 이것입니다.

Confirm-SecureBootUEFI

일반 권한으로 연 PowerShell(Windows PowerShell 5.1)에서는 아래처럼 막혔습니다.

Unable to set proper privileges. Access was denied.

이 명령은 펌웨어 변수를 직접 읽기 때문에 관리자 권한이 필요합니다. 시작 메뉴에서 PowerShell을 오른쪽 클릭해 '관리자 권한으로 실행'을 고르면 되지만, 회사 PC처럼 관리자 권한이 없는 경우도 많습니다. 게다가 이 명령은 보안 부팅이 켜졌는지만 알려 주고, 인증서가 바뀌었는지는 말해 주지 않습니다. 그래서 방향을 바꿨습니다.

관리자 권한 없이 읽힌 레지스트리 값

Microsoft 문서 KB5068202는 인증서 교체 진행 상황을 레지스트리 한 곳에 적어 둔다고 안내합니다. 이 값은 일반 권한으로도 읽혔습니다.

Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\SecureBoot\Servicing" | Select-Object UEFICA2023Status, WindowsUEFICA2023Capable

이 노트북의 결과입니다.

UEFICA2023Status         : Updated
WindowsUEFICA2023Capable : 2

봐야 할 값은 UEFICA2023Status 하나입니다. 처음에는 NotStarted였다가, 교체가 시작되면 InProgress로, 새 키와 새 부팅 관리자가 모두 배포되면 Updated로 바뀝니다. 한국어 문서에는 이 값이 '업데이트됨'으로 번역돼 있지만, 실제 레지스트리에 찍히는 글자는 영어 Updated입니다. 한국어 단어를 찾다가 없다고 놀랄 필요는 없습니다.

WindowsUEFICA2023Capable의 2는 "Windows UEFI CA 2023 인증서가 DB에 있고 시스템이 2023년 서명 부팅 관리자로 시작된다"는 뜻입니다. 다만 Microsoft는 이 값을 참고용이라고 못 박고, 상태를 볼 때는 UEFICA2023Status를 쓰라고 적었습니다.

그림 5. 레지스트리 값의 뜻 (출처: Microsoft 지원 KB5068202 「보안 부팅을 위한 레지스트리 키 업데이트」, 2026-10-13 캡처)

시스템 로그에 남은 1808 다섯 줄

값이 언제 바뀌었는지도 궁금해서 시스템 로그를 찾았습니다. Microsoft 문서 KB5016061은 보안 부팅 인증서 관련 기록을 System 로그에 TPM-WMI라는 이름으로 남긴다고 설명합니다. 이것도 일반 권한으로 읽혔습니다.

Get-WinEvent -FilterHashtable @{LogName='System'; Id=1801,1808} -MaxEvents 10 | Select-Object TimeCreated, Id
TimeCreated              Id
-----------              --
2026-10-10 오전 7:42:00  1808
2026-10-04 오전 11:43:22 1808
2026-09-29 오전 8:59:43  1808
2026-09-20 오후 8:13:45  1808
2026-09-16 오전 6:49:49  1808

1808은 "This device has updated Secure Boot CA/keys"라는 정보 이벤트입니다. 필요한 인증서가 모두 펌웨어에 들어가고 부팅 관리자가 Windows UEFI CA 2023 서명판으로 바뀌었을 때 남습니다. 문서의 주석은 이 이벤트가 기기가 완전히 업데이트됐다는 뜻이라고 적었습니다.

그림 6. 이벤트 1808의 뜻 (출처: Microsoft 지원 KB5016061 「Secure Boot DB and DBX variable update events」, 2026-10-13 캡처)

여기서 한 가지는 알 수 없었습니다. 처음 바뀐 날짜입니다. 이 노트북의 System 로그는 2026년 9월 16일 기록부터만 남아 있어서, 그 전에 무슨 일이 있었는지는 로그로 확인되지 않습니다. 9월 16일 이후로는 1808이 며칠 간격으로 반복해 찍혔고, 1801은 한 번도 없었습니다.

1801이 보인다면 뜻이 다릅니다. Windows가 새 인증서를 받아 두었지만 아직 펌웨어에 적용하지 못했다는 오류 이벤트입니다. 1795는 펌웨어가 목록 갱신 중 오류를 돌려줬다는 기록이고, Microsoft는 이 경우 PC 제조사에 펌웨어 업데이트를 문의하라고 안내합니다. 1795와 1796은 다음 재시작 때 다시 시도합니다.

그림 7. 이 노트북에서 읽은 값 정리 (출처: 2026-10-13 직접 확인한 값을 바탕으로 자체 제작)

BIOS는 2024년 4월판 그대로였습니다

명령어 없이 확인하는 길도 있습니다. 키보드에서 Windows 키와 R을 함께 누르고 msinfo32를 입력하면 '시스템 정보' 창이 열립니다. Microsoft 가정용 안내 문서(KB5062711)가 보안 부팅이 켜졌는지 볼 때 쓰라고 하는 화면입니다.

그림 8. 시스템 정보의 BIOS·보안 부팅 줄 (출처: 이 글을 쓴 노트북 화면, 2026-10-13 캡처. 기기 이름·사용자 이름 줄은 잘라 냄)

'보안 부팅 상태'가 '설정'이면 켜져 있는 것입니다. 이 화면에서 눈에 띈 것은 BIOS 줄이었습니다. 펌웨어 버전 P07ALN.260.240415.SH, 날짜는 2024년 4월입니다. 인증서는 펌웨어 안에 저장되는데 BIOS를 한 번도 바꾸지 않았는데도 교체가 끝나 있었습니다. Windows 업데이트가 펌웨어 안의 KEK·DB 값을 직접 고쳤다는 뜻입니다. 이 노트북에 최근 깔린 보안 업데이트는 9월 15일자 KB5129195였습니다.

삼성전자 공지도 같은 내용입니다. 2026년 5월 6일 고객서비스 알림(No.63)은 갤럭시 북4 이후 제품에는 새 인증서가 처음부터 들어 있고, 갤럭시 북3를 포함한 이전 제품은 Windows 업데이트로 자동 적용되므로 별도 조치가 필요 없다고 적었습니다. 2025년 하반기부터 순차 적용 중이라는 설명도 붙어 있습니다.

그림 9. 삼성전자 보안 부팅 인증서 공지 (출처: 삼성전자 고객서비스 알림 No.63, 2026-05-06 등록, 2026-10-13 캡처)

같은 공지에는 드문 경우의 대처도 있습니다. 갤럭시 북3 이하에서 'Secure Boot Violation' 화면이 뜨며 부팅이 안 되면, 전원을 켜면서 F2로 BIOS에 들어가 Boot 메뉴의 Secure Boot Control을 Off로 바꾸고, BitLocker 복구 화면이 나오면 48자리 복구 키를 입력하라는 안내입니다. 부팅이 아예 막혔을 때 쓰는 복구 절차이고, 멀쩡히 켜지는 PC에서 미리 끄라는 말은 아닙니다. Microsoft 가정용 안내도 새 인증서를 받은 뒤 드물게 BitLocker 복구 화면이 뜰 수 있다고 적고 있으니, 복구 키가 어디에 저장돼 있는지 미리 알아 두는 편이 안전합니다.

다른 문구가 보일 때 할 일

내 PC의 Windows 보안 앱에 위 그림 1과 다른 문구가 보일 수 있습니다. KB5087130은 문구를 여섯 가지로 나눠 할 일을 적어 두었습니다. 자주 볼 만한 넷을 추리면 이렇습니다.

그림 10. 보안 부팅 칸 문구별 할 일 (출처: Microsoft KB5087130을 바탕으로 자체 제작)

'이전 부팅 신뢰 구성을 사용하고 있습니다'라는 문구가 가장 흔할 것으로 봅니다. 이때 할 일은 설정 > Windows 업데이트에서 밀린 업데이트를 모두 설치하고, 재시작하라는 안내가 뜨면 재시작하는 것입니다. 업데이트를 일시 중지해 두었다면 풀어야 합니다. Microsoft 문서는 교체가 월간 업데이트마다 대상 기기를 늘려 가는 방식이라고 설명하고, 2026년 9월 공지에서는 일부 기기가 인증서 업데이트 뒤 한 번 더 재시작할 수 있다고 했습니다.

'하드웨어 또는 펌웨어 제한' 문구는 Windows가 혼자 바꿀 수 없는 기기라는 뜻입니다. 이때는 PC 제조사 지원 페이지에서 보안 부팅 관련 펌웨어(BIOS) 업데이트가 있는지 찾아야 합니다. Microsoft는 이런 펌웨어 업데이트가 제조사의 지원 기간 안에 있는 기기에만 나온다고 적었습니다.

그림 11. 상세 메시지 여섯 가지 원문 (출처: Microsoft 지원 KB5087130 「Windows 보안 앱의 보안 부팅 인증서 업데이트 상태」, 2026-10-13 캡처)

Windows 10 PC와 '2027년 만료' 보도

Windows 10은 2025년 10월 14일에 지원이 끝났습니다. Microsoft 보안 부팅 FAQ(KB5068008)는 그 뒤의 보안 업데이트, 보안 부팅 인증서 업데이트까지를 확장 보안 업데이트(ESU)에 등록한 PC만 받는다고 적었습니다. 소비자용 ESU 등록 기한은 2027년 10월 12일입니다. 지원이 끝난 Windows 10을 ESU 없이 쓰고 있다면, 보안 부팅 칸의 문구가 바뀌기를 기다려도 바뀌지 않습니다.

10월 11일과 12일에는 'MS 인증서가 2027년에 만료돼 일부 PC가 업데이트를 못 받는다'는 보도가 이어졌는데, 원문인 Microsoft Windows IT Pro 블로그 글(2026년 10월 8일)을 열어 보면 보안 부팅 인증서 이야기가 아닙니다. PC가 Windows 업데이트 서버에 접속할 때 '진짜 Microsoft 서버인지' 확인하는 데 쓰는 인증서이고, 만료일은 2027년 5월 17일과 6월 19일입니다. 이 블로그 글에는 Secure Boot라는 단어가 한 번도 나오지 않습니다.

그림 12. 두 인증서 비교 (출처: Microsoft KB5062710, Windows IT Pro 블로그 2026-10-08을 바탕으로 자체 제작)

두 인증서는 놓친 결과도 다릅니다. 보안 부팅 인증서를 못 받으면 PC는 그대로 켜지고 부팅 단계 보안 수정만 빠집니다. 업데이트 연결 인증서를 놓치면 블로그 표현대로 Windows 업데이트에서 '모든 종류의 업데이트'를 받지 못하게 됩니다. 대신 이쪽은 조건이 단순합니다. Windows 11 25H2 이상은 할 일이 없고, 24H2는 2025년 9월 보안 업데이트 이상을, 그 밖에 지원 중인 Windows 11·10은 2026년 7월 보안 업데이트 이상을 2027년 6월 19일 전에 설치해 두면 됩니다.

10월 19일 전에 해 둘 순서

이 노트북에서 해 본 순서를 다른 PC에서도 그대로 쓸 수 있게 묶으면 아래와 같습니다. 어느 단계에서 'Updated'나 '적용되었습니다' 문구를 보면 거기서 끝내도 됩니다.

첫째, Windows 보안 > 장치 보안 > 보안 부팅 칸의 문구를 읽습니다. 녹색 표시가 아니라 '필요한 모든 인증서 업데이트가 적용되었습니다'라는 글자를 봅니다. 칸이 아예 없다면 Windows 업데이트가 밀려 있거나 회사가 관리하는 PC일 수 있습니다. Microsoft 문서에 따르면 회사 관리 PC에서는 이 표시가 기본으로 꺼져 있습니다.

둘째, 문구가 다르면 설정 > Windows 업데이트에서 업데이트를 끝까지 설치하고 재시작합니다. 일시 중지가 걸려 있으면 풉니다.

셋째, 더 확실히 보고 싶으면 PowerShell에서 아래 두 줄을 실행합니다. 관리자 권한은 필요 없었습니다.

Get-ItemProperty "HKLM:\SYSTEM\CurrentControlSet\Control\SecureBoot\Servicing" | Select-Object UEFICA2023Status
Get-WinEvent -FilterHashtable @{LogName='System'; Id=1801,1808} -MaxEvents 10 | Select-Object TimeCreated, Id

첫 줄이 Updated이고 둘째 줄에 1808이 보이면 끝난 것입니다. NotStarted나 InProgress, 또는 1801이 보이면 업데이트와 재시작을 한 번 더 하고 며칠 뒤 다시 봅니다. 그래도 그대로면 PC 제조사의 펌웨어 업데이트를 찾을 차례입니다.

10월 19일이 지나도 새 인증서는 받을 수 있습니다. Microsoft FAQ는 인증서가 이미 만료된 뒤에도 누적 업데이트로 새 인증서를 적용할 수 있다고 적었습니다. 날짜에 쫓겨 보안 부팅을 끄거나 출처를 모르는 '인증서 수동 업데이트' 파일을 받을 이유는 없습니다.
